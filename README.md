## 設計方針

**「自分に合う相手が見つかりそう」→「相談したい」** を最短で成立させる順序にしました。

1. **ヒーロー** — 症状を言い当てる（なかなか会えない／続かない）
2. **2択** — 自分はどちらかを選ばせ、当事者にする
3. **出会いの母数** — 「結婚を考えている人が11万人」。ここで**相手が見つかりそう**と感じてもらう
4. **進め方** — 見つけた後どうするか。手順と支援範囲
5. **実績** — 本当にできるのか。数字＋設計者
6. **事例** — 自分と同じ状態から変わった人がいる
7. **料金** — いくらか
8. **向き不向き〜FAQ〜最終CTA** — 最後の不安を消す

旧版は 悩み → 原因 → IBJ → Before/After → メソッド → 支援内容 と、**解決策に入るまで6セクション**かかっていました。新版は3つ目でIBJの母数、4つ目で支援内容に到達します。

### 配置：支援内容と実績のあいだ

```
支援内容（何をするか）
   ↓
★ 設計した理由（なぜやるか）  ← 新設
   ↓
実績（本当にできるのか）＋ 設計した人
   ↓

```

**「何を」→「なぜ」→「できるのか」→「実際どうか」** という順序にしました。手法の説明（支援内容）の直後に理由を置くことで、それまで読んできた手順が「なぜこの形なのか」の答えとして回収されます。そのうえで実績・経歴・事例と、裏づけが続く構成です。

料金の直前ではなく実績の前に置いたのは、**熱量を先に伝えてから残りを読ませたい**ためです。金額の直前だと、感情に訴えて判断を鈍らせる印象になりかねません。
